RPMS: the data and core logic

This is the core of OpenRPMS. The FOIA files go in, and a working RPMS server comes out. That server holds the records and the rules, and answers the RPCs every application calls.

From the public files to a working server

  1. 1 · In

    The FOIA files

    What IHS has made public: a database copy from 2021, the source code it chose to release, and the patches published since. They are the pieces of a working system, without instructions for putting them back together.

  2. 2 · Build

    A release, kept at the certified level

    Every input is checksummed, the patches are installed to the certified line, the old site's leftover state is cleared, and checks run before anything is published. The same release runs on InterSystems IRIS and on the open-source YottaDB. How a release is built covers the recipe and what is still missing.

  3. 3 · Out

    Working images

    A release becomes images that start a running RPMS server. Install RPMS runs one on your own machine. Try it opens the public demo, with test data only.

  4. 4 · Interface

    The RPCs

    The server answers named requests, called RPCs. They are how every application reads and writes the record. RPCs explains them and counts what a release registers.
