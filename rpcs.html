RPCs

An RPC, or remote procedure call, is a named request an application sends to the RPMS server. "Get this patient's allergies." "Sign this note." "Book this slot." The server runs the matching program and sends back the answer.

RPCs are where the data and core logic meet the applications people use. The chart, the patient panel, and the web front end all work this way, so a new application that speaks RPCs can work alongside them on the same record.

How applications reach them

An application connects to the server through a broker, signs on as a user, and then sends RPCs. The server checks that the user is allowed to call each one. RPMS has three brokers:

  • XWB, the standard broker from VistA.
  • CIA, which VueCentric uses.
  • BMX, which the .NET programs, such as iCare, use.

The rpms-rpc library wraps those connections and the most-used RPCs in plain methods, with examples that sign on and ask a running server for something real. The web front end on Applications is built on it.
